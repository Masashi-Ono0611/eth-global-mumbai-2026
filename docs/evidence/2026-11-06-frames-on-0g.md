# Robot camera frames on 0G Storage: first upload and backfill (6 Nov 2026, 21:06 IST)

Kris asked for the robot's camera frames to be stored on 0G as proof of the robot's work. The frames are
uploaded plain, with no privacy constraint, and R2 stays the fast copy. The code is d022c9b. The evidence uploader first
uploads each chip-signed frame's exact JPEG bytes to 0G Storage. Then it uploads the episode JSON, which now names
the frame's root in `observations[].rootHash` next to its sha256. `EpisodeLog` anchors that episode, so the chain links
it to its frame. The 0G decision still never receives an image.

## Independent check, outside the app

The frame of `jg2wabvwez4mxe22ecnfjvigbq` was downloaded from 0G Storage by its root with plain `curl`, without our
code or keys. Its bytes hash to the digest the chip signed, and the file is a JPEG:

```
$ curl -s "https://indexer-storage-testnet-turbo.0g.ai/file?root=0x0140f6b7b4f719129e98e0c178a88c44786337ad2e78f0ea48414e9e21a4560d" -o f.jpg
$ sha256sum f.jpg
2310ce908068aef102f9be50b07a667b3380acae386e511fca9e1aa7420ed323  f.jpg
$ head -c 4 f.jpg | xxd
00000000: ffd8 ffe0                                ....
$ stat -c %s f.jpg
8683
```

The same episode's JSON, downloaded from 0G Storage by its root `0x11040dfc…8c6c`, names that frame. Its
`observations` entry is
`{"sha256":"0x2310ce90…d323","bytes":8683,"capturedAt":1793972248007,"chipSig":"0x33fc0b54…221b","rootHash":"0x0140f6b7…560d"}`.
That JSON is the one `EpisodeLog` anchors, so the chain links the episode to its frame. The owner's Verify (`POST
/api/wallet/episodes/:id/verify`) does the same download and re-hash and reports `observations[].zeroG {downloaded,
hashMatches, inEvidence}`.
