| Spending authority | MetaMask Delegation Framework v1.3.0 delegations with caveats (ValueLte 0, ERC20PeriodTransfer daily cap, Timestamp expiry, and our `RobotPaymentPolicyEnforcer`: per-payment cap, payee allowlist, approval signature). Revoke is a relayed `disableDelegation`. Each grant has a unique salt | **D1 is a mirror, never an authority** |
| Payments | x402 v2 on the grant path only. The chip signs a one-time leaf (ExactExecution, Id = invoice hash, Timestamp, Redeemer); our ERC-7710 facilitator verifies, simulates and settles via `redeemDelegations`. The float path is dropped. About $0.010 to $0.013 per settle (simulated) | after a pull to the chip, Arc no longer binds payee, invoice or revocation; S2 spike 14/14 on live Arc state |
| Owner actions | The passkey signs one-time delegations the relayer redeems (deploy, revoke). No bundler; ERC-4337 via Pimlico's public bundler is the documented break-glass | a relayer cannot steal or redirect, only delay |
| Robot Agent | One errand state machine per robot, an Effect service over D1 (no Durable Objects, WebSockets or MCP). It calls 0G, asks the chip to sign, submits to the merchant and logs evidence | 28 h, and the foundation's DO wiring is unproven |
| Chip link | HTTPS long-polling: pair with a signed challenge, 25 s polls for sign requests, a 35 s lease. With no lease the motors stop and signing is refused | works behind any NAT with nothing new in the foundation |
| MCP | Off the critical path; a read-only MCP server is a stretch | MCP adds interoperability, not security |
| 0G Compute (per message since 7 Nov 00:15) | The 0G router (`https://router-api.0g.ai/v1`, hackathon key, expires 13 Nov). The owner picks the brain per message in the dock: `glm-5.3` (TeeML, TEE proof stored with each decision, the default) or `qwen3-vl-plus` (labelled "Not TEE-verifiable"). The choice is stored on the intent and episode. No automatic fallback; `decide` retries one 429 inside its 10 s budget. Only a stored, verified TEE proof earns the badge | when glm-5.3's provider answered 429 for twenty minutes, Kris chose a visible switch over a silent fallback that would blur the TEE story |
| 0G | The decision model gets structured input (item, price, budget, policy) and returns `pay / ask_human / walk_away` via a tool; every call is logged with its request id. **A failed call ends the errand in `safe_stop`, never a faked decision.** Episodes go to 0G Storage (Galileo) and `EpisodeLog`, uploaded by a Bun process on netcup. The 0G judges confirmed Galileo is fine (7 Nov) | prize text; the storage SDK can't run in Workers |
| World | Agent Pass only (World IdP OIDC). A payment over the per-payment cap or to an unlisted payee needs the owner's approval in World App, with `nonce` = the payment's hash. The backend verifies the token (`iss`, `aud`, `exp`, `nonce`, `auth_time`, `acr` Orb, `jti` once, `sub` = owner) and co-signs that one payment; deny or expiry signs nothing. `amr` is recorded, not judged (95a92bd), and PKCE is S256 (2b04027). `auth_time ≥ approval created_at − 60 s`, up to 300 s looser than §9, accepted for the event. On-chain verification is the stretch. IDKit and HumanRegistry are dropped | prize text; on-chain checks would publish the owner's World pseudonym (D15); World.test.ts 10 cases |
| Robot evidence: scans and QR crops (6 Nov 16:50 IST) | `POST /api/chips/:robotId/scans` (chip bearer token, EIP-191 signature over `vitaquack-scan:v1|invoiceId|sha256|capturedAt|robotId`) starts the errand for exactly the scanned invoice and stores one chip-signed QR crop (≤ 64 KB) in R2.
