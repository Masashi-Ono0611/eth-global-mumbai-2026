# 0G: Compute (Private Computer / Router), Storage, Chain research

Researched 2026-11-05 (event day 1). Everything below was checked against live docs, live endpoints
(`curl`) or cloned source unless it is listed under "Open questions / unverified".

## TL;DR

- **Inference:** the **0G Compute Router**, branded **"0G Private Computer"** at <https://pc.0g.ai>, is an
  **OpenAI-compatible** API at `https://router-api.0g.ai/v1`.
  - Auth is `Authorization: Bearer sk-…`.
  - It is paid from an on-chain 0G deposit (the "Payment Layer"), or USD via Stripe.
  - No SDK is needed. Use the `openai` npm client or plain `fetch`.
  - Every response carries **`x_0g_trace.request_id`** plus the provider address and the exact cost. That
    is our per-decision evidence.
- **Vision + sealed inference in one model:** `0gm-1.0-35b-a3b` (0G's own model) takes **text + image** and
  is **TeeML** (Intel TDX, dstack). It costs about $0.08 / 1M input and $0.48 / 1M output tokens. Pair it with
  `verify_tee: true` and the `X-0G-Provider-Trust-Mode: private` header.
- **Evidence:** upload the per-episode JSON to **0G Storage** with `@0gfoundation/0g-storage-ts-sdk`
  (`MemData` → `indexer.upload`). That returns a `rootHash` and `txHash`.
- **Contract addresses are required** in the Physical AI submission. Deploy a tiny `EpisodeLog` contract on
  0G Chain that anchors `(episodeId, rootHash, requestIds)`, or similar.
- **Prize rule that shapes the design:** "A safe-stop fallback if 0G is unreachable. **A fallback that fakes
  the decision disqualifies.**" If 0G is down, the duck must stop and not pay. No local-model fallback.

### Request and response (<https://docs.0g.ai/developer-hub/building-on-0g/compute-network/router/features/chat-completions>)

- Standard OpenAI body, plus `response_format: {"type":"json_object"}` and `tools` on models that support them.
- Images go in `messages[].content[]` as `{"type":"image_url","image_url":{"url":"data:image/jpeg;base64,…"}}`.
  **Send base64, not URLs.** The limit is 20 MB per request.
- Router extensions:
  - `verify_tee: true`
  - routing headers: `X-0G-Provider-Trust-Mode: standard|verified|private`, `X-0G-Provider-Sort: latency|price`,
    `X-0G-Provider-Address`, `X-0G-Provider-Max-Price-Usd-*`
- Every response contains:
  ```json
  "x_0g_trace": { "request_id": "0852f405-…", "provider": "0xd996…", "billing": {"input_cost":"…","output_cost":"…","total_cost":"…"}, "tee_verified": true }
  ```
  Costs are in **neuron** (1e18 neuron = 1 0G). Error bodies also carry a top-level `request_id`.
- **Independent TEE check** (<https://docs.0g.ai/developer-hub/building-on-0g/compute-network/router/features/verifiable-execution>):
  - Read the **`ZG-Res-Key`** response header (the chatID, falling back to `id`).
  - Then call `broker.inference.processResponse(providerAddress, chatID)` with `@0gfoundation/0g-compute-ts-sdk`
    and any wallet on `https://evmrpc.0g.ai`.
  - Or do it manually: `GET {providerUrl}/v1/proxy/signature/{chatID}?model=…` → EIP-191 sig by `teeSignerAddress`.
- **Trust tiers** (<https://docs.0g.ai/developer-hub/building-on-0g/compute-network/router/privacy>):
  - `private` = TeeML only (sealed: the model runs in TDX + GPU TEE). If no TeeML provider is available it
    returns **503 `no_provider_for_trust_mode`** and never silently downgrades.
  - `verified` = TeeML + TeeTLS.
  - `standard` = anything.
- **Errors** (<https://docs.0g.ai/developer-hub/building-on-0g/compute-network/router/errors>):

  | Code | Meaning | Retry? |
  | --- | --- | --- |
  | 400 | bad request | no |
  | 401 | bad or revoked key | no |
  | **402 `insufficient_balance`** | out of funds | no |
  | 403 | forbidden | no |
  | 429 | rate limited | yes, honour `Retry-After` |
  | 502 `provider_error` | failover exhausted | maybe |
  | 503 `no_available_provider` | no provider | maybe |

  Rate-limit headers: `X-RateLimit-*`.

## 3. Storage: facts (<https://docs.0g.ai/developer-hub/building-on-0g/storage/sdk>)

- `npm i @0gfoundation/0g-storage-ts-sdk ethers` (SDK **1.2.13**).
  - It has a **peer dependency on exactly `ethers@6.13.1`**.
  - An older name, `@0gfoundation/0g-ts-sdk` 1.2.8, is used by the starter kit.
  - It imports Node `fs` and `crypto`, so run it on the backend, not on the robot MCU.
- In-memory upload:
  ```ts
  import { Indexer, MemData } from '@0gfoundation/0g-storage-ts-sdk'
  const indexer = new Indexer(INDEXER_RPC)                 // flow contract auto-discovered
  const data = new MemData(new TextEncoder().encode(JSON.stringify(episode)))
  const [tree, e1] = await data.merkleTree()              // must run before upload
  const [tx, e2] = await indexer.upload(data, RPC_URL, signer) // → { rootHash, txHash }
  ```
  Download with `indexer.download(rootHash, outPath, true)` (Node only). Client-side AES-256/ECIES
  encryption is supported. A KV store (`Batcher`, `KvClient`) also exists.
- **Turbo** (faster, higher fee) vs **Standard** networks use different indexers.
- Explorer: `storagescan-galileo.0g.ai` (testnet).
- Uploads are on-chain txs and need 0G for gas and fees.

## 6. Our integration, mapped onto the duck demo

### Decision loop: 0G is "the brain, not the spinal cord"

```
voice/text "Duck, buy me <item>"  (optional: whisper-large-v3 on 0G)
→ walk to the stand (on-device motion: Open Duck Mini / Microduck policy; no 0G here)
→ camera frame + decoded QR {merchant, amount, memo} + owner policy {perTxCap, remaining, restricted categories}
→ DECIDE on 0G: POST router-api.0g.ai/v1/chat/completions
     model=0gm-1.0-35b-a3b, verify_tee=true, header X-0G-Provider-Trust-Mode: private,
     response_format=json_object, image as base64
     → {item_matches: bool, item_seen: str, price_sane: bool, category: "food"|"age_restricted"|…,
        action: "pay" | "ask_human" | "walk_away", reason: str}
→ the action drives the body and the money:
     pay        → robot signs the Arc USDC payment with its session key (on-chain caps still apply)
     ask_human  → World Agent Pass approval (see world.md); approve → co-signed pay; deny/expire → walk away
     walk_away  → duck turns around and shakes its head
→ CONFIRM (optional second 0G call): photo of the merchant screen / receipt → "paid?"
```

0G decides *whether* and *what*; Arc enforces *how much*; World supplies *the human*. That is also a
clean story for judges about why each sponsor is load-bearing.

### Per-decision evidence (prize: "episode log on 0G Storage with a request id per decision")

Each decision record contains:

```
{ episodeId, step, ts, model, request_id: x_0g_trace.request_id, chat_id: ZG-Res-Key,
  provider, tee_verified, cost_neuron, inputHashes: {imageSha256, qrPayload}, output (decision JSON),
  outcome: {arcTxHash | worldApprovalId | "walked_away" | "safe_stop"} }
```

- At the end of the episode, `MemData` upload → `rootHash` + `txHash` on 0G Storage.
- Then `EpisodeLog.record(episodeId, rootHash, keccak(requestIds))` on 0G Chain. This gives us the
  **required contract address**, and the dashboard can link to chainscan + storagescan.
- Optionally run `processResponse` independently for each decision and store the result. That is stronger
  than trusting `tee_verified`.
- "Replayable": a `replay` page that downloads the episode by `rootHash` and re-renders frames and
  decisions. Simulation is also eligible, so a MuJoCo/Open_Duck_Playground replay is an option if the
  hardware fails.

### Safe-stop (must not fake a decision)

| Trigger | Duck behaviour |
| --- | --- |
| Request timeout (e.g. 8–10 s; tune after measuring 0gm latency) | stop, "brain offline" face/LED, **no payment** |
| 5xx / 503 `no_provider_for_trust_mode` / `no_available_provider` | stop, no payment |
| 402 `insufficient_balance` | stop, no payment |
| `tee_verified === false` | treat as untrusted, stop, no payment |
| Malformed JSON | stop, no payment |

- Log a `safe_stop` record (with the error `request_id` if there is one) and upload it when connectivity returns.
- The duck **never** uses a local heuristic to choose `pay`.
- A local "stop and stay still" is allowed (that is the spinal cord, not a decision).
- Show this live: pull the Wi-Fi or revoke the `sk-` key mid-demo, and the duck freezes.

### Where the keys live

The `sk-` key and the storage signer key live on the **backend** (the docs: "Never ship keys to browsers";
the Storage SDK needs Node). The robot sends frames + QR to our backend, and the backend calls 0G. Options:

- Run the backend on the Pi itself, as long as the key does not go onto the ESP32.
- Use one `sk-` key per robot, so revoking a robot also kills its brain.
- Use `mk-` keys only for the dashboard balance view.

### Mainnet or testnet

- The Router is funded from the Payment Layer (both networks have an address). The docs' verification
  sample uses mainnet RPC, so assume **the Router runs on mainnet**.
- For storage and the `EpisodeLog` contract, Galileo testnet is free (faucet) but limited to 0.1 0G/day.
  Mainnet needs real 0G.
- Recommendation: **Router on mainnet (event credits), Storage + EpisodeLog on Galileo** unless the booth says
  judges want mainnet. Decide at the workshop today.
